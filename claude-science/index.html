3. Methods you can reuse

A. Evidence-first literature review

  1. Write one precise research question and list the sources the agent can use.
  2. For each paper, save its DOI or stable URL, claim, method, dataset, and numerical result.
  3. Record source access. Mark a paywalled or missing paper as not read.
  4. Use one agent to write a summary and a separate agent to check every claim.
  5. Make the figures from the evidence table. Check them against the raw data.

Based on the Allen Institute workflow. The Scientist reports that errors and inaccessible paywalled papers remain real problems. Read the interviews.

B. Candidate generation and external tests

  1. Write the success criteria before the agent starts.
  2. Save every candidate ID and the reason for its selection.
  3. Separate predicted scores from measured results.
  4. Have an independent test, reviewer, or baseline check the short list.
  5. Publish the failed cases and limits, not only the best examples.

The 2026 protein-design work is a strong example of this pattern. It also shows that many candidate designs and large compute budgets may be needed.

C. Reproducible compute

  1. Start with a small test run and a fixed input set.
  2. Record code version, environment, random seed, parameters, and output paths.
  3. Use a job scheduler for cluster work. Do not run heavy workloads on login nodes.
  4. Review job scripts and resource limits before you approve execution.
  5. Replay the saved code. Compare its outputs with the agent's written claim.

Lawrence Berkeley National Laboratory documents how Claude Science submits Slurm jobs through SSH, keeps jobs running after laptop disconnects, and copies back the outputs. Its guide warns that remote jobs run with the user's cluster permissions. Read the HPC guide.

4. Practical tips and known limits

  1. Use a bounded task. Ask for one decision, figure, reproduction, or test. State the success rule.
  2. Give the agent a verified tool. Reuse your lab's scripts and data readers as skills where possible.
  3. Keep an evidence table. Save original values and links before you ask for prose.
  4. Use independent review. A second agent can find issues. Human review or independent tests are still necessary.
  5. Fork for fair comparisons. Keep baseline and improved methods on the same data, seed, and compute budget.
  6. Make failed runs visible. Keep error logs, negative outcomes, and changes to the plan.
  7. Use persistent Python or R sessions for iteration. Avoid loading large data again when the session can reuse it. Save a clean runnable version too.
  8. Give SSH hosts written limits. State scratch directory, job scheduler, partitions, GPU quotas, and files that must not be changed. Never place passwords or keys in prompts or public pages.
  9. Review approvals. Do not give remote jobs unrestricted access only to remove approval prompts. Remote jobs use your account permissions.
  10. Track usage. Claude Science consumes usage from the linked Claude plan and can be token-intensive. See Anthropic's usage guidance.

Limitations reported by researchers: mistaken citations or summaries, no direct access to some paywalled papers, incomplete judgment of study quality, and occasional blocked legitimate biology queries. A reviewer agent is useful, but it is not proof that a result is correct. Independent account.

Data caution: Work can run on a local system, but material read as model context is sent to the model service under the applicable data policy. Do not assume that a local workflow means no data leaves your machine. Product policy details.

5. Three starter prompts for research

Prompt 1. Reproduce before you improve

Goal: Reproduce one public result from the paper [title and URL].
First read the method and report missing information.
Use the original data split and baseline if available.
Do not claim a result without logs and measured values.
Save code, package versions, seed, run command, and output table.
Stop after a small test and show the evidence before a full run.

Prompt 2. Find a real research gap

Question: [one precise research question].
Find primary papers and record each paper's DOI or stable URL.
For each paper, extract: method, dataset, metric, main claim,
key numerical result, and stated limitation.
Mark inaccessible papers as not read.
Group real disagreements and missing tests.
Propose three falsifiable experiments with fixed baselines.
Then ask an independent reviewer to challenge the conclusions.

Prompt 3. Run a fair ML experiment

Compare method A with baseline B on the same data.
Freeze the split, seed, model size, and evaluation code.
Give both the same resource budget.
Define the primary metric before the run.
Run a small dry test first. Show expected costs and job script.
Record time, resource use, failed trials, and all metrics.
Return a table with links to logs, code, and saved artifacts.
Do not change the success metric after seeing the results.

Quick pilot: how to measure value

Choose three public tasks: a literature evidence table, a published result reproduction, and one small ablation. For each task, record human time, agent usage, errors found by review, successful reruns, and final scientific quality. Use the same acceptance criteria for the agent and the manual baseline. Keep unsuccessful tasks in the comparison.
